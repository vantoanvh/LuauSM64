# Goddard oracle

Headless, deterministic native reference for Goddard (the 3D engine of the title screen and game over Mario head, `reference/src/goddard/*.c`, vanilla n64decomp sm64 US). The native game build stubs Goddard (`native/stub/goddard.c`), so this is a separate executable: `build/goddard_oracle.exe`. It compiles the real, unmodified Goddard sources 64-bit, calls them the way the game does, and writes one 64-bit FNV-1a hash per frame of a frame stream a Luau port can reproduce without matching 64-bit pointers.

Nothing outside `native/goddard/` is touched. Generated textures are reused from `native/build/us` (`textures/intro_raw/*.inc.c`); `build.sh` stops if that tree is missing (`../build.sh generated` makes it).

## Commands

```
sh build.sh                      # build/goddard_oracle.exe (gcc 64-bit, flags of native/Makefile, NO_SEGMENTED_MEMORY)
sh run.sh                        # traces/<name>.goddard.hash for every line of traces/manifest.txt
sh check.sh                      # determinism: two runs + the -O0 gcov build against each other and against the committed hashes
sh coverage.sh                   # gcov build, all traces, writes coverage.txt
sh preview.sh                    # preview/*.png software renders of single frames
node tools/gen_traces.mjs        # regenerates traces/*.trace

build/goddard_oracle.exe <id> <trace> <hash-out> [<dump-out|-> [<dump-from> [<dump-to> [<ppm-frame> <ppm-out>]]]]
```

`id`: 2 = regular head (title screen, `GD_SCENE_REGULAR_MARIO`, `animate_mario_head_normal`), 3 = dizzy head (game over, `GD_SCENE_DIZZY_MARIO`, `animate_mario_head_gameover`, then the normal animation). The dump is written only for frames `dump-from..dump-to` (default all; `-` = no dump file), so a single frame is cheap: `... /tmp/h.txt /tmp/d.txt 100 100`. Frame 0 dumps about 60k lines. Stdout shows commands / vertices / triangles of frames 0, 100 and the last.

Traces (`traces/manifest.txt`, trace format of `docs/state-hash.md` without `boot`/`do`; all generated by `tools/gen_traces.mjs`, the cursor model is in its header):

| trace | id | frames | content |
| --- | --- | --- | --- |
| `idle` | 2 | 600 | no input (the head flies in, opening animation) |
| `idle_long` | 2 | 2400 | no input (nodding, dozing off, waking up) |
| `stick_circles` | 2 | 680 | stick circles, full deflection corner pushes, spiral; no button |
| `grab_drag` | 2 | 862 | A grabs at the screen center and drags; B, Z, Start, L, R, C, D-pad taps; two more grabs at corners |
| `camera_controls` | 2 | 820 | B zoom cycle, held C buttons, L, D-pad, R freeze with a released ear, Start toggle |
| `grab_sweep` | 2 | 1250 | idle until the head is close, then A presses on a 24 pixel grid: every grabber picked (pinch / let go sounds) |
| `gameover` | 3 | 649 | dizzy animation, stick circles, A drags, Start / Z / B |

## How Goddard is called (driver/main.c)

As in `level_script.c` `level_cmd_load_mario_head`: `gdm_init(pool, 0xE1000 * 2)` (`DOUBLE_SIZE_ON_64_BIT`), `gd_add_to_heap(zbuffer, 0x25800)`, `gd_add_to_heap(framebuffers, 3 * 0x25800)`, `gdm_setup()`, `gdm_maketestdl(id)`. Static zero initialized arrays stand for the pool, z buffer and framebuffers (the N64 does not zero RAM; the oracle verifiably does not read uninitialized pool memory, see Determinism).

Per trace line, as in `geo_draw_mario_head_goddard` and `display_and_vsync`: `gd_copy_p1_contpad(&pad)` (OSContPad: buttons, stick x, stick y, errnum 0), `dl = gdm_gettestdl(id)`, `sfx = gd_sfx_to_play()`, `gd_vblank()`. Then the frame stream is taken.

Note on the order: in `display_and_vsync` the vblank callback (`gGoddardVblankCallback = gd_vblank`) runs before `exec_display_list`, so the RCP reads the display list after `gd_vblank` (which, via `convert_net_verts`, writes the final `Vtx` data of the list). The oracle therefore expands the list and hashes the scene state after `gd_vblank`.

## Frame stream (hashed per frame)

FNV-1a 64 over the bytes below (`docs/state-hash.md`: offset basis `0xcbf29ce484222325`, prime `0x100000001b3`, a fresh hash per frame, lines `<frame> <16 hex digits>` in the hash file). Integers are little endian, signed ones two's complement, `f32` is the IEEE binary32 bit pattern (`-0.0` differs from `0.0`).

1. `sfx`: s32, `gd_sfx_to_play()` (a `GD_SFX_*` bitset).
2. Display list stream: the list returned by `gdm_gettestdl` is walked depth first. For each command (`driver/dl_walk.c`):
   * `u8 op` (the F3D_OLD opcode, `gbi.h`), `u32 w0` (the 32-bit first word; the 64-bit builds keep it in the low half).
   * then by opcode:
     * `G_MTX` (0x01): 64 bytes of the `Mtx` (16 s32 words in memory order, `guMtxF2L` int / frac packing).
     * `G_MOVEMEM` (0x03), index = `(w0 >> 16) & 0xff`: `0x80` viewport: 16 bytes (`Vp`, eight s16). Index `0x82` to `0x94` (lookat x / y, lights, ambient slot), 16 byte slots: only the data bytes `col[3]`, `colc[3]`, `dir[3]` = bytes 0..2, 4..6, 8..10 (the pad bytes are never written by Goddard). A slot loaded from the address of a `Lights` struct (the ambient light) holds ambient `col`/`colc` and `l[0].col` in bytes 8..10. Anything else aborts the oracle.
     * `G_VTX` (0x04): `w0 & 0xffff` bytes of `Vtx` (16 bytes each: `s16 ob[3]`, `u16 flag`, `s16 tc[2]`, `u8 cn[4]`; `cn` is color or normal).
     * `G_DL` (0x06): nothing more. The target list's records follow immediately (nested, no marker). `(w0 >> 16) & 0xff` is 0 for a call (the parent continues after the child's `G_ENDDL`) or 1 for a branch (the parent list ends after the child's records).
     * `G_SETTIMG` (0xfd), `G_SETZIMG` (0xfe), `G_SETCIMG` (0xff): `u16 image id`, `u32 byte offset` into that image. Ids 0..24 are the static texture arrays of `renderer.c` in this order: `hand_open`, `hand_closed`, `red_star_0..7` (2..9), `white_star_0..7` (10..17), `sparkle_0..5` (18..23), `mario_face_shine` (24). Ids 25, 26, 27: the z buffer and the two colour buffers of the screen view (`sScreenView->zbuf`, `colourBufs[0]`, `colourBufs[1]`; the actual addresses come from Goddard's allocator and are not part of the stream). The oracle aborts on a pointer that is none of these.
     * every other opcode (all remaining commands, including `G_TRI1`, `G_ENDDL`, `G_MOVEWORD`, `G_TEXTURE`, the RDP commands): `u32 w1`. The oracle aborts when `w1` has bits above 32 (an unhandled pointer).
   * after the last record: `u32` number of command records, `u32` number of vertices loaded by `G_VTX`.
3. Scene state (`driver/scene_hash.c`, `wrapper/*.c`), in this order:
   * `gGdObjCount`, `gGdGroupCount`, `gGdPlaneCount`, `gGdCameraCount`, `gGdMoveScene`, `gGdUseVtxNormal` (s32), `D_801A8058` (f32).
   * `gGdCtrl` then `gGdCtrlPrev`: `unk00`, `dleft`, `dright`, `dup`, `ddown`, `cleft`, `cright`, `cup`, `cdown`, `btnA`, `btnB`, `trgL`, `trgR`, `unk4C`, `unk50`, `newStartPress` (s32); `stickXf`, `stickYf`, `unk88`, `unkA0`, `unkAC` (f32); `dragStartX`, `dragStartY`, `stickDeltaX`, `stickDeltaY`, `stickX`, `stickY`, `csrX`, `csrY` (s32); the seven bitfield flags `dragging`, `unkD8b40`, `unkD8b20`, `startedDragging`, `unkD8b08`, `unkD8b04`, `AbtnPressWait` (u8 each); `dragStartFrame`, `currFrame` (u32). Fillers and `prevFrame` are skipped.
   * renderer statics: `gGdFrameBufNum` (s32), `sAlpha` (s16), `sNumLights`, `sLightId`, `sMtxParamType` (s32), `sGdDlCount` (u32), `sTimeScaleFactor` (f32), `sUpdateYoshiScene`, `sUpdateMarioScene`, `sUpdateCarScene` (s32), `sAmbScaleColour` (3 f32), per light 0..1: `sLightScaleColours[i]` (3 f32) and `sLightDirections[i]` x, y, z (s32), `sGdContPads[0]` button (u16), stick x, y (u8 each), `sPrevFrameCont[0]` the same.
   * `debug_utils.c`: `sPrimarySeed`, `sSecondarySeed` (u32). `sfx.c`: `sCurrSfx`, `sPrevSfx` (u32).
   * `s32` object count (the length of the list `gGdObjectList`), then every object from the list head (newest first, through `next`): `s32 type`, `s16 index`, `u16 drawFlags`, then the fields of its type in declaration order (`hash_*` functions; the struct definitions are in `gd_types.h`). A pointer to an object is `s32` of its `index` (-1 for NULL); `char` arrays are the bytes up to and including the NUL (a fixed buffer is cut at its size); `Mat4f` is 16 f32 row major; `GdVec3f` 3 f32. Skipped: `filler*` arrays, function pointers (`objDrawFn`, `updateFunc`, `controlFunc`, `valfn`), `gbiVerts`, `ObjView` buffers (`zbuf`, `colourBufs`, `proc`), `ObjMaterial.texture`, `ObjLabel.fmtstr`, `ObjValPtr.offset`. Groups hash their member `index` list only when `linkType` is 0 (linkType 1 groups point to static compressed data: animation data, vertex data, face data). Joint, net, vertex, face, camera, animator (frame, state, nods, stillTimer), particle, light, shape, material, weight, view, gadget, label, valptr, zone and plane objects are all covered, so the positions, rotations, joint / net / vertex positions, particle state, controller state and animation counters of the scene are in the hash.

`index` is `gGdObjCount` at creation, unique and deterministic, so a port that creates objects in the same order reproduces it.

## Dump format

For a dumped frame: `frame N`, `sfx=..`, then one line per command `cmd <n> depth=<d> <NAME> w0=<hex> w1=<hex>` (pointer commands show the decoded payload below: matrix words, viewport / light slot, `vtx[i] pos=.. flag=.. st=.. cn=..`, `image=<name>+<offset>`; `DL` lines say `call` or `branch`), then the totals, then `scene` and `name=value` lines for the scene state (floats as `0x<bits> (<%.9g>)`). Diff two dumps of the same frame to find the first mismatching command or field.

## Determinism

* No wall clock: `osGetTime` returns 0 (stub/os.c). Goddard uses it for debug timers and in `gd_rand_float` (`sPrimarySeed ^= time`), which is seeded with fixed constants; with time 0 the random sequence (sparkle particles) is a pure function of the seed.
* No uninitialized reads: autos are zero initialized (`-ftrivial-auto-var-init=zero`); the pool, z buffer and framebuffers are static arrays. Checked: a build that fills them with `0xAA`, `0xFF` gives identical hashes for every trace (this found the light pad bytes, which are why `G_MOVEMEM` hashes only data bytes).
* `check.sh`: every trace twice, plus the `-O0 --coverage` build, all compared with each other and with `traces/*.goddard.hash` (the hashes do not depend on optimization level or addresses). Result: `check passed`.
* `sinf` / `cosf` (goddard `gd_sin_d` / `gd_cos_d`, `guRotate`, `guPerspective`) are replaced by `(float) sin((double) x)` / `cos` (`stub/math.c`, `-Dsinf=oracle_sinf -Dcosf=oracle_cosf`): the C library `sinf` of the toolchain differs from that by one ulp for some arguments (hashes diverge from frame 66 of `idle`), while a Luau port using `math.sin` / `math.cos` rounded to f32 matches (checked: Luau's `math.sin` / `math.cos` equal C `sin` / `cos` on 20000 random arguments). The N64 libultra `sinf` (`lib/src/math/sinf.c`) is a third variant and is not used.

## 64-bit changes and workarounds (reference/ is not edited)

* `wrapper/renderer.c`, `wrapper/debug_utils.c`, `wrapper/sfx.c`: `#include` the real file (compiled as that translation unit) and add accessors for its file statics (textures, screen buffers, seeds, sound bitsets, light and update state). The code of the real files is unchanged.
* `wrapper/renderer.c` renames `gd_exit` (`#define gd_exit oracle_unused_gd_exit` around the include): in the game it is an endless loop, every Goddard fatal error goes through it. `stub/os.c` defines `gd_exit` to print a message and exit with 3 instead of hanging. Never triggered by the traces.
* `-Dsinf`/`-Dcosf` as above. Flags otherwise as `native/Makefile` (`-std=gnu90 -O1 -fsigned-char -fno-strict-aliasing -fwrapv -ffp-contract=off -ftrivial-auto-var-init=zero -fcommon -w`, `VERSION_US F3D_OLD NON_MATCHING AVOID_UB _FINALROM _LANGUAGE_C NO_SEGMENTED_MEMORY`).
* Compiled unchanged and linked: all `reference/src/goddard/*.c` and `dynlists/*.c`, and `reference/lib/src/gu*.c` (`guMtxF2L`, `guPerspective`, `guOrtho`, `guRotate`, `guTranslate`, ... as in the game build).
* `stub/os.c` (libultra): `osCreateMesgQueue`, `osRecvMesg`, `osSetEventMesg`, `osContInit`, `osContStartReadData`, `osViSetSpecialFeatures`, `osViSwapBuffer`, `osVirtualToPhysical` (identity, `NO_SEGMENTED_MEMORY`), `osGetTime` (0). `osPiStartDma`, `osMapTLB` are not needed (`load_dynlist` is a direct `proc_dynlist` under `NO_SEGMENTED_MEMORY`). No game symbols were needed.
* The 64-bit preparation of the sources (`uintptr_t` casts, `AVOID_UB`, `DOUBLE_SIZE_ON_64_BIT`) was sufficient: no source change was forced. `Gfx` words are `uintptr_t`; the first word is always 32 bits, pointers are only in the second word (checked by the oracle).

## Coverage (`coverage.txt`)

gcov of the `-O0` build over all traces: 319 of 621 functions of `src/goddard` executed (51.4%), 330 of 638 with `lib/src/gu*`. Never executed: scenes 0, 1, 4, 5 of `gdm_maketestdl` (Yoshi and car, never loaded by the game), file / shape loading (`get_3DG1_shape`, `gd_fopen`, ...), debug views and timers display, menu / gadgets (`old_menu.c`), the `stub_*` functions, `__main__`, `gd_init_controllers`, `gd_exit` and the `fatal_*` paths. The list per file is in `coverage.txt`.

## Sanity check that the head is produced

Frame 0 (idle): 3446 commands, 2968 vertices loaded, 1337 triangles; frame 100: 3371 commands, 2956 vertices, 1331 triangles. `preview.sh` renders frames with a small Fast3D emulation (`driver/preview.c`: matrices, lighting, z buffer; textures ignored, sprite quads skipped): `preview/idle_frame590.png` is the head, `idle_frame0.png` is tiny because the head starts far away and flies in, `grab_drag_frame170.png` a dragged face, `gameover_frame100.png` the dizzy animation.

## Open problems and risks for a port

* The `G_SETCIMG` / `G_SETZIMG` identity is the role of the buffer, not an address; a port must keep which of the three screen view buffers each command names.
* `guMtxF2L` converts `f32 * 65536` to `s32` in C; the oracle's x86-64 conversion saturates to `0x80000000` on overflow, the N64 does not. No overflow occurs in the traces.
* `Mtx` is 64 bytes because `long` is 32 bit with this toolchain (Windows); an LP64 build would make `Mtx` 128 bytes and change the stream.
* Function pointers of objects are not hashed; the animation function is visible through the animator `state` / `frame` fields.
* Allocation addresses and heap layout (sizes are 64-bit sizes) are not observable; only `index`, counts and values are.
* Scenes 0, 1, 4, 5 and the debug views are not covered.
